## 一、保留下来的做法（下个项目继续用）

- **brainstorm → spec → plan → SDD 四段式**。先用视觉伴侣把"扁平卡通 × 数字具象化"的风格在浏览器里敲定（避免了文字描述的反复），再写规格、再写逐任务计划、最后子代理驱动执行。方向在写第一行代码前就锁死，15 个 Task 没有一次推倒重来。
- **作者与评审严格分离（规则 D）**。每个 Task：executor 实现 → Explore 做 spec 逐字比对 → code-reviewer 做质量审，三者不同 subagent。这一层抓出了真问题：Hero 的 FOUC、竞速 km/h 35 vs 36 矛盾、第三章 once 惯例不一致、第四章云影越界、移动端竞速球压标签（HIGH）。同 context 自审绝抓不到这些。
- **浏览器实测而非肉眼估**。动效/布局类验收一律用 Playwright 取计算样式与几何量（球的 transform 位移、label.left − ball.right 间隙、能量条宽度、高度尺读数），用数字判 PASS。移动端球压标签的根因（dist 没算球的 offsetLeft 布局起点）就是靠逐条量间隙发现的——肉眼"看着差不多"会漏掉。
- **模型 TDD + 浏览器一致性双锁**。实验室物理模型先写 11 个单测（速度表 ±15% 校准 + 三预设结局 + 融化分支），再在浏览器实测四个预设输出与单测逐一吻合。数值正确性在两个层面交叉验证。
- **累积 todo 显式入账**。评审中暂不处理的项（ch2 axis 运行时判定、.speed-row 别加 opacity:0、安全卡留白）写进 `_progress.json` 的 todos，到 Task 14 一次性清掉，没有一条丢失。
- **每步 checkpoint 留档**。`.omc/evidence/checkpoints/` 逐章存目检截图 + 数据，复盘和回归时一眼可查。

## 二、必须补上的缺口（下次开工前先想清楚）

- **计划里的常量该先验算再写进文档**。计划写"8 个单测"实际是 11（test.each 展开口径），cloudShade、dist 这些几何常量也是在浏览器实测后才发现固定值不够（dist 的 130 没算 offsetLeft、80 对最宽标签差 3-4px，最终改成按 label.offsetWidth 自适应）。教训：带魔法数字的几何/计数，计划阶段就应标注"待实测校准"，别当成定论。
- **响应式应在静态骨架阶段就过一遍移动端**。竞速横向轴、球压标签这些问题到 Task 14 才集中爆发，根因是 Task 4 写骨架时只验了桌面。下次骨架阶段就该在 375 宽过一遍，把响应式断点的结构问题提前。
- **dev server 生命周期要纳入流程**。中途会话中断后 dev server 仍在、但实现者偶尔在验证步骤中断（Task 11/12 都发生过"文件写好未提交"），靠主控 git status 兜底续跑。下次应在派单模板里明确"验证→提交"是一步、并让实现者报告 git log 确认。

## 三、关键决策复盘

- **去掉 Three.js**（设计阶段）。风格从"暗黑风暴 WebGL"转向"扁平卡通"后，及时把技术栈从 Three.js 改成 SVG + Canvas 2D。结果：产物 gzip 仅 53 KB、Lighthouse 93。若当时没改，体积和性能都会差一个量级。**风格定了立刻回头审技术栈**是对的。
- **raceLanes 保留速度表真实值、不被模型覆盖**（Task 3/10）。第二章展示科普事实（用户给的速度表），第四章实验室是带免责声明的简化模型，两处数字允许不同。评审一度想用模型值"修正"速度表，主控裁决保留事实值并加警示注释。**科普准确性 > 内部一致性**。
- **FOUC 用 html.js 门控而非纯 CSS 预隐藏**（Task 8）。纯 CSS opacity:0 会破坏"无 JS 可读"的规格要求。改成首帧前内联脚本加 .js 类、CSS 用 html.js 门控、入场 from 改 fromTo 显式终值。**渐进增强的预隐藏必须只在 JS 可用时生效**。
- **YAGNI 一以贯之**。ParticleField 的 destroy()、非空断言收口、motion 常量化等"防御性"建议反复出现，每次都按"实例与页面同生命周期、单页不重挂载"裁决不采纳，避免了为不会发生的场景增加复杂度。但 cheap 且有文档价值的（clearProps 清残留、ScrollTrigger.refresh 硬化、各处意图注释）则采纳。**判断标准是"是否防住真实路径上的问题"，不是"是否更防御"**。
- **合并前补两处硬化**（终审后）。终审已判 Yes，但采纳了它优先的 2 条 MINOR：竞速清残留轴变换（resize 跨断点重赛的真实边缘 bug）、总装后 ScrollTrigger.refresh（pin 撑高文档后背景层端点测量的标准实践）。**"可合并"不等于"无可改进"，廉价且防真问题的就在合并前收掉**。
