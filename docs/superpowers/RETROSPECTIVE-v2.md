# 冰雹科普网页 v2 升级 — 项目复盘

日期：2026-11-11
体量：Tier 2（10 步：基线修复 → 地基 → 五章并行 → 总装 → 评审与事实抽检 → 文档）
分支：feat/v2-upgrade（未合并 main、未 push）
结果：57 个单测通过；JS gzip 64.9 KB（上限 75）；Lighthouse 性能 94 / 无障碍 100；
两个视口锚点读数与规格一致；无 JS 与 reduced-motion 全文可读；20 条科普事实核对 0 条丢失或改值。

## 一、保留下来的做法

- **先实测再定方向。** 开工前把 v1 跑起来逐屏截图并取数，才发现「天空和高度尺提前走完」不是设计问题而是测量缺陷（背景层在第一章 pin 撑高文档之前测量，少算 2400px），第二章白字不可读是它的连带症状。先修缺陷再谈重设计，避免了围着一个 bug 去改配色。
- **一个核心想法管全局。** 「页面即大气剖面图，跟着同一颗冰雹落地」把高度尺、天空、主角、章节顺序绑到同一条高度上。五个人并行各画各的，最后拼起来不散，靠的是这条主线加规格 §3 的插画与色彩规则，而不是事后统一。
- **天空从「固定层逐帧改色」改成「文档等高的渐变」。** 每一章背后的颜色只取决于它在文档里的位置，文字对比度变成可计算的确定量（全页最低 5.1:1），也顺带消掉了逐帧改色和测量时机两类问题。
- **作者与评审分离，且评审真的读库源码。** 地基评审读 GSAP 源码发现触屏设备忽略「只改高度」的 resize——手机地址栏收起后读数会卡在 0.1 km。这在 DevTools 模拟器里复现不出来，所有基于视口模拟的验收都会漏掉它。
- **每个并行代理自带无头浏览器。** 五章并行时共享一个 MCP 浏览器会互相抢。提前在临时目录装好 playwright-core 并写一个 `open()` 辅助模块，每个代理写自己的脚本实测，验收数字都来自各自独立的浏览器实例。
- **事实清单写进规格、收尾全量核对。** 20 条事实在规格 §8 列明，由没参与改写的代理逐条对照 v1 原文核对，并反向检查有没有新增的事实性陈述。

## 二、必须补上的缺口

- **规格里我自己写进了没有出处的内容。** 应季提醒的「5–7 月」、图注的「典型实测值」都是规格作者（主控）随手写的，实现者照做，直到事实抽检和主控复看才发现。教训：规格里凡是新增的事实性措辞，写的时候就要标来源或标「待核」，不能因为是自己写的就免检。
- **逐章容错只做了一半。** 地基阶段给入口加了每章 try/catch，但没有同时规定各章预隐藏样式的失败出口，结果五章各自写了只在 `html.js` 下生效、依赖本章 JS 成功才解除的预隐藏，合并后才被评审抓到。教训：容错是跨层契约，入口和样式两侧要在同一步定下来，并写进给并行实现者的通用说明。
- **同一类缺陷出现了两次。** 「缓存的绝对滚动值在手机地址栏伸缩后失效」在旅程层修过一次，结尾交棒又犯了一次。第一次修完就该把它写成通用规则发给后续实现者。
- **worktree 隔离的基点不是当前分支。** 隔离工作区建在 main 而不是 feat/v2-upgrade 的 HEAD 上，五个代理都得先自行快进。这次他们都发现并处理了，但不该靠运气——派单时应写明「先确认基点包含某提交」。
- **真机没有测。** 两处手机地址栏相关的修复都只在无头浏览器的触屏上下文里验证过；iOS 回弹、visualViewport 更新时机是否一致不确定。合并前应在一台真机上滚到底看一次。
- **一个已知的小出入留着没动。** 第一章孕育区色带画在 5–10 km，标签写 −10℃～−30℃，按图内气温轴这两个温度对应约 6 与 9 km。这是 v1 两条原始事实叠加直减率的结果，文案有「约」字，未改。

## 三、关键决策复盘

- **保留扁平卡通与技术栈（用户决定）。** 没有重开美术方向，也没有引入框架或 WebGL。升级全部花在工艺和叙事上，产物从 50 KB 涨到 65 KB，换来 MotionPath、实验室舞台和结局地图。
- **高度按章节锚点分段映射，而不是按滚动比例。** v1 的线性映射让读数和内容永远对不上。分段后「1.5 km = 云底分界 = 天空转亮 = 戴上安全帽」是同一刻。代价是多了一层锚点测量，需要处理 pin、字体换入、地址栏伸缩。
- **物理模型不改。** 实验室所有新可视化（剖面舞台、结局地图）都由原 `simulate` 的输出驱动，原有 11 个单测原样通过。第二章曲线图里典型值的圆点不完全落在模型曲线上，图注明说「这是对的」——延续 v1「科普准确性 > 内部一致性」的裁决。
- **字体只自托管拉丁与数字。** Fredoka 约 30 KB 让数字成为主角；中文走系统栈。途中发现两处坑：圆体在 ≥600 字重下被合成加粗糊字（降到 500 并禁用合成），Fredoka 的 unicode-range 会抢走中文破折号与引号（收窄范围）。
- **移动端竞速从横向条带改回纵向四列。** v1 为了窄屏把赛道横过来，带来错轴、球压标签等一串问题；v2 让冰雹在所有宽度下都往下落，这类问题从结构上消失。
- **结局地图的颜色没有和第三章色带完全统一。** 实验室四档用蓝 / 黄 / 橙 / 红（按明度排序，色觉障碍下可分辨），第三章 1 cm 档是绿。两章语义不同（结局 vs 危险等级），接受这个不一致。
