# 冰雹科普网页 v3（动画精修 + 公式排版）— 项目复盘

日期：2026-11-11
体量：Tier 2（地基 → 三路并行 → 合并总装 → 独立评审与公式验算 → 文档）
分支：feat/v2-upgrade（未合并 main、未 push）
起因：v2 完成后用户看过页面，反馈「已经相当好了，想让动画更精良、可爱，让数学公式看起来更专业」；
中途又反馈「公式部分有些密集，看着很挤」。
结果：80 个单测通过；JS gzip 70.7 KB（上限 75）；Lighthouse 性能中位 96 / 无障碍 100；
v2 的八条既有保证在合并后的 HEAD 上逐条重测成立；公式独立验算 0 处错误；最终评审裁决「通过」。

## 一、保留下来的做法

- **公式的 TeX 由规格写死，事后独立验算。** 上一轮规格作者写进过没有出处的内容，所以这次三块新增公式逐字写在规格里、先自己验算，实现者只负责排版，不许改写物理；之后由没参与的代理从头重推、手算四组参数并与实际运行模型的结果逐位比对。0 处错误。
- **公式构建时预渲染。** KaTeX 只在构建期跑，运行时不带公式库：JS 只涨了 0.2 KB，无 JS 也能显示，TeX 写错或占位漏转换时构建直接失败并报行号。
- **「被测量的元素永远不加待机动画」当作铁律写进规格，并要求举证。** 给球、雹胚、示范冰雹贴脸，加浮动、眨眼、挤压回弹，最容易悄悄破坏的就是 v2 那些靠几何量撑着的保证。三路都按要求采样 30 帧证明被测量元素的包围盒偏差为 0，合并后评审重测八条保证全部成立。
- **地基评审与并行实现同时进行，发现问题立即通知在途的实现者。** 评审指出「只贴脸」的尺寸会悄悄变成 0、SVG 宿主放不进 HTML 的脸，这两个陷阱正是三路马上要大量踩的。当时三路已经开工，直接给它们各发一条带可靠做法的提醒，同时派修复把地基这一侧改掉，并要求新接口向后兼容。三路都避开了，合并零返工。
- **沿用上一轮的回归脚本。** v2 各章作者和评审者留下的验收脚本成了现成的回归套件，三路和评审都复制后重跑。
- **「在场才动」做成约定加自检。** 循环动画必须带 `.anim-loop` 且有被观察的祖先，离屏自动暂停；开发模式下漏了会在控制台警告。评审逐个把循环滚进视口确认都在跑，reduced-motion 下全页动画数为 0。

## 二、必须补上的缺口

- **公式上页后才暴露的跨章矛盾。** 第三章的代入速度取自速度表，第四章的模型在大冰雹端偏低 15–25%，两块公式同时摆上页面后，读者自己代入会得出与正文相反的结论。规格作者写 TeX 时只逐块验算，没有跨块对一遍。地基实现者指出后补了一句说明，而那句话本身又不精确（写成「按小冰雹校准」，实际最贴合的是 2–3 cm，1 cm 反而偏高），靠独立验算才改对。教训：新增的事实性内容要做跨章一致性检查，补说明的那句话同样要过验算。
- **说明文字越补越长，把公式块挤满了。** 每次验算意见都往公式下面加一句，最后用户看到的是一整段密密麻麻的小字。用户指出「很挤」之后才把符号说明拆成图例、加大留白、删掉重复信息。教训：往页面上加说明之前先看一眼版面还装不装得下；「准确」和「读得动」要一起验收，截图自查时不能只看公式本身渲染对不对。
- **接口设计时没有覆盖到已知的使用场景。** 规格明确要求给 SVG 里的雹胚和示范冰雹贴脸、要求实验室雹宝戴着护目镜换表情，但地基交付的接口两样都做不到（脸是 HTML 元素；护目镜绑死在一个表情上），都是评审或下游实现者撞上才发现。教训：地基的验收项里要包含「用新接口把规格里列出的每个用例各做一遍最小演示」。
- **通用说明里的回归脚本信息过期。** 三路都花了时间适配不认识 KaTeX 的旧脚本（公式内部的字符会被当成文字重叠误报），各自改了一份。应该由地基步骤统一交付一份适配好的。
- **真机仍然没有测。** v2 留下的两处手机地址栏修复、这一轮新增的 SVG 对位和独立 transform 属性，都只在无头浏览器里验证过。
- **一个临时工作区被锁定没能清理**，内容已完整合并，留在 `.claude/worktrees/` 下。

## 三、关键决策复盘

- **新增三块公式而不只是美化现有公式。** 用户说的是「让公式看起来更专业」，页面上原本只有 `v ∝ √d` 一处。只换排版的话变化很小，所以把页面和模型已经说过的话写成了式子（受力平衡、动能、模型三式），并在动手前明确告知用户这是新增内容、可以去掉。代价是引出了上面的跨章矛盾和版面密度问题。
- **可爱来自角色的反应，不是到处乱动。** 规格取代了 v2「每章只留一个主菜动画」的规则，但要求每处动画能回答「它为什么动」：落地所以挤压，翻滚所以头晕，破云所以戴上安全帽。1986 年雹灾那张卡明确保持肃静。最终评审对「可爱但不吵」的意见是：第二章落地瞬间是全站最热闹的一处，但不到 1 秒且由读者自己触发，可以接受。
- **脸用 HTML 叠加层，不用 foreignObject，也不复制一份 SVG 标记。** 第一章和第四章各自实现了叠加层（一个用屏幕变换矩阵对位，一个用舞台百分比定位），写法不统一但对位误差都在 0.02px 以内。没有为了统一而重写。
- **太小就不贴脸。** 10px 的黄豆只点两只眼睛，移动端连眼睛也省掉；第四章下限尺寸的小冰雹只画两个点，雨滴用手画的两点加嘴。小到看不清的脸比没有脸更糟。
- **修正了 v2 的一个方向错误。** 第一章融化演示里，水滴原本是从终点下方升上来的，与代码注释「从 0℃ 线落下」相反。第一路实现者在加表情时发现并改正，属于超出任务范围但正确的修正，予以采纳。
- **结尾交棒保留两套粗线画法。** 地基提供了即时切换的 `setDetail`，第三路自己写了能淡入的 `.is-coarse`。两套并存有重复，但淡入效果更好，评审判定不冲突，保留并在此记录。
